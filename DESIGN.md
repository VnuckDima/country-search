## 1. Отмена устаревших запросов (гонка ответов)

**Проблема.** При быстром вводе (например `sp` → `spain`) запрос к `countries.dev/name/sp` может ответить медленнее, чем запрос на `spain`. Если просто игнорировать "поздний" ответ флагом, старый ответ всё равно может прилететь после нового и перезаписать экран актуальным результатом по устаревшему запросу — это баг, вопрос только во времени.

**Решение.** Реальная отмена через `AbortController`:

* при каждом изменении поля ввода (`src/app.ts:124`, `onInput`) вызывается `this.cache.abort(this.currentQuery)` — отменяет текущий полёт через `AbortController.abort()`;
* отмена происходит на событие ввода, а не тогда, когда debounce фактически запускает сетевой запрос, поэтому за время ожидания debounce устаревший запрос уже отменён;
* `searchCountries` передаёт сигнал в `fetch`; при `abort()` fetch отвергает промис `AbortError` (`DOMException` с `name === 'AbortError'`);
* в `app.doSearch` (`src/app.ts:168`) ветка `AbortError` молча возвращается — пользователь не видит ошибку от своей же отмены.

**Почему не флаг.** Флаг "это последний запрос" не останавливает сетевой запрос: в вкладке Network запрос продолжает висеть, при ответе приложение тратит время на рендеринг устаревших данных, а при медленной сети или отключении интернета устаревший ответ успеет прилететь после нового. Только `abort()` реально прерывает запрос (браузер помечает его `canceled/aborted` в Network).

**Таймаут.** Составной сигнал через `combineSignals(AbortSignal.timeout(10000))` (`src/app.ts:150`). `AbortSignal.any` недоступен в используемом jsdom, поэтому `combineSignals` реализован вручную: отменяется при срабатывании любого источника, причина первой отмены сохраняется, чтобы `TimeoutError` не спутать с `AbortError`. В `catch` различаются: `AbortError` — наша отмена, игнорируем; `TimeoutError` — реальная ошибка, показываем пользователю с кнопкой "Повторить".

## 2. Задержка debounce

Выбрана `300` мс (`src/app.ts`). Без дебаунса каждое нажатие клавиши порождает отдельный HTTP-запрос (при быстрой вставке текста — десяток запросов). При увеличении задержки (например 1000 мс) интерфейс становится вялым: пользователь видит результаты с заметной паузой после остановки ввода. 300 мс — баланс между количеством запросов и отзывчивостью.

## 3. Сложность

* `mapCountryResponse` (`src/mapCountryResponse.ts`): **O(L)** по общему размеру массивов `languages`/`currencies` сырого ответа, иначе O(1). Чистая функция, не мутирует вход, тестируется без сети.
* `CountryCache` (`src/cache.ts`): получение из кэша — **O(1)** (`Map.get`), запись — **O(1)**, дедупликация одновременных одинаковых запросов — **O(1)** (второй запрос с тем же текстом использует тот же полётный промис). Каждый вызывающий получает свой промист и свой сигнал отмены: отмена одного вызывающего не ломает промис остальных.

## 4. Принципы чистого кода

* **SRP:** `debounce.ts` — только задержка вызова; `searchCountries.ts` — только сеть и маппинг ответа; `cache.ts` — кэш и дедупликация; `history.ts` — только localStorage; `app.ts` — только DOM и состояние экрана.
* **Pure function:** `mapCountryResponse` не имеет побочных эффектов, результат зависит только от аргумента.
* **Yield/неповторение:** дебаунс, кэш и отмена написаны вручную без сторонних библиотек (lodash и т.п.).
* **Обработка ошибок:** отдельные ветки для `AbortError` (наша отмена, не показываем), `TimeoutError` (реальная ошибка ожидания), `HttpError` (статус 4xx/5xx через `response.ok`, кроме 404), 404 — пустой результат, а не ошибка.
* **Никакого innerHTML:** весь динамический контент создаётся через `document.createElement`/`textContent` (`src/app.ts`).
* **Публичный API без прокси:** запросы идут напрямую к `countries.dev`, CORS поддерживается сервером.

## 5. Бонус

Кэш по строке запроса + дедупликация полётающих запросов (`CountryCache`); история поиска в `localStorage` с повторным поиском по клику (`History`).
